# 直接上传 MinIO 后扫描知识库

1. 在前端“知识库管理”创建或选择知识库。
2. “从 MinIO 导入文档”区域显示该知识库的完整目录，例如 `tellerx-knowledge/imports/<知识库ID>/`。
3. 在 MinIO 的 `tellerx-knowledge` bucket 中创建 `imports/<知识库ID>/` 目录，把原始文档放进去；可以包含子目录。
4. 点击“扫描知识库”。页面显示当前文件、已解析、跳过和失败数量。刷新页面后仍可查看扫描进度。

知识库目录使用稳定 ID；重命名知识库不会改变目录。不要把待导入文档放在 bucket 根目录、其他知识库目录或 `embeddings/` 下。已有通过前端上传的文档无需移动。

## 处理规则

- 支持现有上传功能支持的文件格式及大小上限；目录标记、隐藏/系统文件、不支持的格式、超限文件会跳过。
- 递归扫描当前知识库目录，分页读取 MinIO 列表。不同子目录的同名文件视为不同文档。
- 按相对路径建立逻辑文档身份，下载实际内容计算 SHA-256；内容不变且已经解析成功时不重复解析或调用向量模型，但仍需读取文件来验证内容。
- 新增内容复制到现有不可变对象区，随后解析、向量化并发布索引。扫描导入默认批准，与前端上传默认行为一致。
- 同路径内容变化创建新版本，旧版本保留。输入目录内的文件是可修改的来源；下载和引用使用不可变副本。
- 单文件失败不会阻断后续文件；页面保留最近 100 条跳过/失败明细。修复后可再次扫描重试。
- 从 MinIO 导入目录删除文件不会删除知识库记录。已在知识库软删除的扫描文档会跳过；如彻底清理了记录，源文件仍存在时可再次导入。
- 扫描只读导入目录，不删除来源文件。与现有前端上传相同文件名不自动合并，扫描文档使用独立 `minio:` 逻辑键。

## 部署和接口

需要 `STORAGE_BACKEND=s3`、`RUN_INLINE_INGESTION=true`。MinIO 应用凭证已有本 bucket 的 List/Get/Put 权限，无需扩大权限。

升级前先执行 `.venv/bin/python -m alembic upgrade head`，新增 `knowledge_scans` 表；不重建旧文档或搜索索引。然后重启后端，运行 `npm run build` 更新由后端提供的前端文件（开发模式可直接使用 Vite）。

- `POST /api/v1/projects/{project_id}/scan`：立即返回 202 和扫描任务；同一知识库重复点击返回正在运行的任务。
- `GET /api/v1/projects/{project_id}/scan`：返回是否支持扫描、bucket、前缀及最近一次任务。

进度持久化到数据库，后台顺序处理文件。进程终止后没有独立扫描 worker 自动恢复；一小时无进展的任务会在查询时标记中断，可重新扫描。扫描期间禁止物理清理/删除该知识库。失败入库任务仍可在原文档列表中查看详细原因。

## 本机验证

已验证新增导入、重复跳过、同名覆盖形成版本、中文子目录、隐藏文件跳过、其他知识库隔离和历史版本下载，以及前端点击后展示扫描完成结果。坏文档不会阻断扫描，修复后重扫成功也已验证。后端 142 项测试、前端 28 项测试及生产构建通过。
