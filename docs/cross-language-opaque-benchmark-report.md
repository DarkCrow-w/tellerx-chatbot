# 不透明文件名跨语言知识检索基准报告

## 1. 目标与结论

本基准用于验证：在文件名无法推断业务关联、资料同时包含中文、英文和中英混杂内容、答案必须跨多份文档拼接的情况下，系统能否准确定位证据、拒绝未知实体，并由 Qwen 生成带可追溯引用的结论。

结论：当前实现通过本轮验收。全量 108 问检索基准的 Recall@10、答案关键事实覆盖率、不可回答拒答率和 Excel 来源坐标准确率均为 100%；覆盖六类跨语言问法及三类未知实体的 9 问真实 Qwen 抽样中，回答状态、引用和关键内容准确率均为 100%。

## 2. 语料设计

- 项目：`Codex-CrossLang-Opaque-16-Test`
- 关系簇：16 个；每簇 7 份文档，共 112 份。
- 生命周期：96 份 `approved`、16 份 `draft`。每个关系簇均含一份带错误值的草稿干扰文档。
- 语言：中文 32 份、英文 48 份、中英混杂 32 份。
- 格式：Markdown 32 份；DOCX、XLSX、HTML、PDF、TXT 各 16 份。
- 文件名：统一为 12 位小写十六进制散列加扩展名，例如 `97a22abaea7e.txt`；文件名不包含业务名称、语言提示或关系 ID。
- 关联方式：批准的双语术语登记表负责映射中文业务称谓、英文运行称谓和内部桥接键；下游资料通过控制、运行时、路由、发布等引用号相连，不依赖文件名或自由翻译猜测。
- 内容分布：中文业务规则、英文架构与 API 合约、双语参数表、英文发布记录和双语术语表分别维护不同事实，复杂问题必须跨 2–5 份文档取证。
- 干扰项：历史门槛、退役接口、原型拒绝码、草稿值和近似但不存在的中英文实体。

语料目录：`evaluation/generated/crosslang-opaque-16/`

核心清单：

- `manifest.jsonl`：上传元数据、语言、格式和生命周期。
- `relation-graph.json`：关系簇、别名与内部引用图。
- `questions.jsonl`：96 个可回答问题和 12 个不可回答问题。
- `generation-summary.json`：固定种子和分布统计。
- `upload-report.json`：上传与入库结果。
- `retrieval-v1-r1.json`：全量混合检索报告。
- `answer-report-qwen3.7-plus-2026-05-26.json`：真实 Qwen 回答抽样报告。

## 3. 检索链路修正

本轮首次运行暴露出两个需要区分的问题。

第一，中文业务称谓和英文运行称谓之间不能依赖向量模型自行猜测。检索器现在只从批准的受控术语登记块中提取双语别名和内部引用号，再执行第二次混合检索；未知实体找不到受控映射时直接返回空证据。

第二，按文件名统计命中会掩盖块级缺失：HTML 的标题块可能已进入 Top 10，但真正的 API 路径位于相邻块。检索器现在为已证明相关的文档预留相邻块候选，再经 Rerank；当最终选中的是短标题块时，会在证据预算内附加最近的内容块。基准同时新增“答案关键事实覆盖率”，要求期望值实际存在于返回块正文，而不只是期望文件被命中。

## 4. 问题类型

每个关系簇包含以下六类可回答问题：

1. 中文问题跨到英文运行时、API 合约和失败队列。
2. 英文问题跨到中文治理责任人和中文控制规则名。
3. 中文问题定位中英混杂 Excel 的当前门槛、审批角色和超时。
4. 英文问题串联术语表、Excel 与英文 PDF 发布记录。
5. 中英混合问题比较两个区域的当前参数。
6. 一次综合中文责任人、英文 API、当前门槛和审计保留期，要求引用五份资料。

另外包含中文、英文和中英混合三类未知别名问题，用于验证严格拒答及近似实体隔离。

## 7. 上传与持久化

112 份文档已通过公开上传 API 写入独立项目，112 个摄取任务全部成功，无重复上传。PostgreSQL 保存项目、文档、版本、任务和原始文件元数据；Elasticsearch 保存可重建的 BM25 与向量索引。继续向该项目添加文档时，沿用普通上传流程即可，不需要重新生成或重置现有索引。

## 8. 可重复执行命令

生成或刷新语料（固定种子，默认保留已有报告）：

```bash
node scripts/generate-crosslang-opaque-corpus.mjs
```

全量检索基准：

```bash
docker compose run --rm --no-deps \
  -v "$PWD/evaluation/generated/crosslang-opaque-16:/app/evaluation/generated/crosslang-opaque-16" \
  api knowledge-benchmark retrieve evaluation/generated/crosslang-opaque-16
```

固定 Qwen 模型回答基准：

```bash
docker compose run --rm --no-deps \
  -v "$PWD/evaluation/generated/crosslang-opaque-16:/app/evaluation/generated/crosslang-opaque-16" \
  api knowledge-benchmark answers evaluation/generated/crosslang-opaque-16 \
  --limit 6 --model qwen3.7-plus-2026-05-26
```

说明：`--limit 6` 会选择六个可回答问题，并自动加入三个不可回答问题。扩大样本会产生更多 Qwen token 和时间成本。

## 9. 当前边界

- 本轮结果证明该合成分布下的跨语言检索和证据编排可行，不等价于真实业务语料的最终准确率。
- 真实上线前仍需用业务专家标注的 50–100 个真实问题复验，尤其覆盖企业缩写、同名系统、版本替换和表格异常。
- 端到端 P95 主要由外部 Qwen 生成延迟决定，已经单独保留检索耗时；若要求稳定在 10 秒内，需要进一步做生成流式输出、超时预算和模型延迟分层。
- 双语别名必须来自批准的受控术语资料。没有映射时系统会拒答，这属于准确性保护，而不是用模型自由翻译补齐关系。
